Definition of `PrePost`: $\mathbb{P} \times (A \to \mathbb{P})$
```ocaml
ret v = (True, fun a => a = v)
(* m = (pre, post) *)
(* f = fun a => (pre' a, post' a) *)
bind m f = ( pre /\ forall a, post a -> pre' a,
             fun b => exists a, post a /\ post' a b )
```
Usual ordering:
```ocaml
Definition PrePost_le {A} ((pre1, post1) (pre2, post2) : PrePost A) : Prop :=
  (pre2 -> pre1) /\ (forall a, post1 a -> post2 a)
```
"Twisted" ordering (this is the one that I will use, but counterexamples are also given for the usual ordering):
```ocaml
Definition PrePost_le_tw {A} ((pre1, post1) (pre2, post2) : PrePost A) : Prop :=
  (pre2 -> pre1) /\ (forall a, pre2 -> post1 a -> post2 a)
```

First, what is the right observation of a program into the `PrePost` monad? In the base case:
1. The precondition slot has four natural candidates (listed below). Since it has to be a monad morphism, the two options marked with an `x` are excluded. Another way to think about this is that the `pre` slot is the only place to record divergence, since the postcondition takes a resulting value of type `A` and we represent divergence as `option A`. 
	1. `True`, 
	2. `False`, `x` (fails `ret` monad morphism law)
	3. computation diverges (for `d : divndNE A`, where `d` is a computation in the base nondeterministic, nonterminating computation monad, `unOptionT d None`) `x` (again, for `ret` monad morphism law, since `ret` cannot diverge)
	4. computation terminates (`~ unOptionT d None`)
2. The postcondition slot should say something about the output of the computation.
So, there are two options:
```ocaml
Definition prepost1 {A} (d : divndNE A) : PrePost A :=
  ( True, 
    fun a => unOptionT d (Some a) )
    
Definition prepost2 {A} (d : divndNE A) : PrePost A :=
  ( ~ unOptionT d None,
    fun a => unOptionT d (Some a) )
```

For example, for:
```ocaml
pp2wp(pre,post) := fun q => pre /\ forall a, post a -> q a
```
we can show that:
$$pre \sqsubseteq \theta_{\mathsf{WP}}(m)(post) \iff \text{pp2wp}(pre,post) \sqsubseteq \theta_{\mathsf{WP}}(m)$$

We would want to show that:
$$pre \sqsubseteq \theta_{\mathsf{DWLP}}(m)(post) \iff \theta_{\mathsf{PrePost}}(m) \sqsubseteq \text{dwlp2pp}(pre,post)$$
Note: we want the theta on the left side, since in the ordering whatever `P` is in the embedding must imply `True`. If it was flipped, then it would force `pre` to only be `True`. 

Here are the embeddings that work:
DWLP Under / ASP Over:
```ocaml
dwlpasp2pp(pre,post) = (pre, post)
```
$$pre \sqsubseteq \theta_{\mathsf{DWLP}}(m)(post) \iff  \theta_{\mathsf{prepost1}}(m) \sqsubseteq \text{dwlpasp2pp}(pre,post)$$
```ocaml
(pre -> True) /\ (forall a, pre -> R_m a -> post a)
(* precondition ordering represents that divergence is allowed
   if pre holds, then everything that terminates must be in post - R_m a := unOptionT d (Some a) says a is a terminating result *)
```
$$\theta_{\mathsf{ASP}}(m)(pre) \sqsubseteq post \iff  \theta_{\mathsf{prepost1}}(m) \sqsubseteq \text{dwlpasp2pp}(pre,post)$$
DWP Under:
```ocaml
dwp2pp(pre,post) = (pre, post)
```
$$pre \sqsubseteq \theta_{\mathsf{DWP}}(m)(post) \iff  \theta_{\mathsf{prepost2}}(m) \sqsubseteq \text{dwp2pp}(pre,post)$$
```ocaml
(pre -> ~ unOptionT d None) /\ (forall a, pre -> R_m a -> post a)
(* precondition ordering represents that divergence is *not* allowed, ~ unOptionT d None needs to be True
   if pre holds, then everything that terminates must be in post - R_m a := unOptionT d (Some a) says a is a terminating result *)
```
AWP Over / DSLP Under: (contrapositive)
```ocaml
awpdslp2pp(pre,post) = (~ pre, ~ post)
```
$$\theta_{\mathsf{AWP}}(m)(post) \sqsubseteq pre \iff  \theta_{\mathsf{prepost1}}(m) \sqsubseteq \text{awpdslp2pp}(pre,post)$$
$$post \sqsubseteq \theta_{\mathsf{DSLP}}(m)(pre) \iff  \theta_{\mathsf{prepost1}}(m) \sqsubseteq \text{awpdslp2pp}(pre,post)$$
AWLP Over: (contrapositive)
```ocaml
awlp2pp(pre,post) = (~ pre, ~ post)
```
$$\theta_{\mathsf{AWLP}}(m)(post) \sqsubseteq pre \iff  \theta_{\mathsf{prepost2}}(m) \sqsubseteq \text{awlp2pp}(pre,post)$$
ASP Under:
```ocaml
asp2pp(pre,post) = (pre \/ forall a, ~ post a, fun a => pre /\ post a)
```
$$post \sqsubseteq \theta_{\mathsf{ASP}}(m)(pre) \iff   \text{asp2pp}(pre,post) \sqsubseteq \theta_{\mathsf{prepost1}}(m) $$
```ocaml
(True -> (pre \/ forall a, ~ post a)) /\ (forall a, True -> pre /\ post a -> R_m a)
(* precondition ordering: either pre holds or the postcondition is empty.
   If pre fails and post is non-empty, no computation satisfies the spec,
   matching the triple, which then fails for every computation.

   postcondition ordering: if pre holds, every element of post must be in    the terminating set (R_m).
*)
```
DSLP Over: (contrapositive)
```ocaml
dslp2pp(pre,post) = (~ pre \/ forall a, post a, fun a => ~ pre /\ ~ post a)
```
$$\theta_{\mathsf{DSLP}}(m)(pre) \sqsubseteq post \iff   \text{dslp2pp}(pre,post) \sqsubseteq \theta_{\mathsf{prepost1}}(m) $$

Here are the counterexamples for AWP Under; DWLP Over and DWP Over are contrapositives, so similar counterexamples work. 

Consider four computations:
- `m1` returns 1
- `m2` returns 2
- `m3` returns 3
- `m13` returns 1 or 3
Consider `p := True` and `q := fun a => a = 1 \/ a = 2`. For AWP Under, one run must end in `q`. This holds for `m1`, `m2`, and `m13`, and fails for `m3`. Since there is no divergence, `prepost1 = prepost2`, so:
- `prepost1 m1 = (True, {1})`
- `prepost1 m2 = (True, {2})`
- `prepost1 m3 = (True, {3})`
- `prepost1 m13 = (True, {1, 3})`
Consider the following embedding:
```ocaml
awp2pp(pre,post) = (P, Q) (* for some P and Q *)
```
If it is `prepost(m) <= awp2pp(True, {1,2})`, then accepting `m13` needs `P -> True` and `P -> {1, 3} <= Q`. If `P` is `False`, then every computation is accepted, including `m3`. If `P` is `True`, then `{3} <= Q`, so `m3` also must be accepted. 

If it is `awp2pp(True, {1,2}) <= prepost(m)`, then `True -> P`, forcing `P` to be `True`, and `Q <= R_m` for every accepted `m`. If `m1` and `m2` need to be accepted, then `Q <= {1}` and `Q <= {2}`, so `Q` is necessarily the empty set. However, since the empty set is included in `{3}`, `m3` must also be accepted. 

Since there is no divergence, the same counterexample works for AWLP Under.

Stateful setting:
Stateful `PrePost`: `(S -> Prop) * (S -> A * S -> Prop)`
```ocaml
(* m = (pre, post),  f = fun a => (pre' a, post' a) *)
ret v    = ( fun s => True,
             fun s r => r = (v, s) )

bind m f = ( fun s => pre s /\ forall a s', post s (a, s') -> pre' a s',
             fun s r => exists a s', post s (a, s') /\ post' a s' r )
```
Twisted ordering:
```ocaml
Definition PrePostSt_le_tw {S A} ((pre1, post1) (pre2, post2) : PrePostSt S A) : Prop :=
  forall s, (pre2 s -> pre1 s) /\ (forall r, pre2 s -> post1 s r -> post2 s r)
```
The two monad morphisms:
```ocaml
Definition prepost1 {S A} (m : stdivndNE S A) : PrePostSt S A :=
  ( fun s => True,
    fun s r => unOptionT (runStateT m s) (Some r) )

Definition prepost2 {S A} (m : stdivndNE S A) : PrePostSt S A :=
  ( fun s => ~ unOptionT (runStateT m s) None,
    fun s r => unOptionT (runStateT m s) (Some r) )
```

The taxonomy diagram and our monadic relation results give some intuition for why these triples. DWLP and ASP transformers are isomorphic (our section 6) and DWLP Under and AWP Over are isomorphic (via the contrapositive relation, section 4). 

Additionally: this seems to indicate that you really do need a predicate transformer to do *any* notion of incorrectness. Lisbon logic is *not* representable as an embedding into the `PrePost` monad. And, as before, incorrectness logic is still out of reach. 

The counterexample for ASP Under and DSLP Over not being embeddable in their monads is in section 5.4 of the paper. Here are the counterexamples for the PrePost case:

Consider two start states `s1` and `s2` and two distinct outcomes `r1` and `r2` with the following computations:
- `m1` ends in `r2` when started in `s1` and in `r1` when started in `s2`
- `m2` ends in `r1` when started in `s1` and in `r2` when started in `s2`
- `m` reads the start state, then runs `m1` from `s1` and `m2` from `s2`, so it ends in `r2` from both start states and never reaches `r1`
Consider `p := True` and `q := {r1}`. The ASP Under triple holds  for `m1` and `m2` but *not* `m`. Since nothing diverges, `prepost1 = prepost2`. So:
```ocaml
prepost m1 = s1 ↦ (True, {r2}), s2 ↦ (True, {r1})
prepost m2 = s1 ↦ (True, {r1}), s2 ↦ (True, {r2})
prepost m = s1 ↦ (True, {r2}), s2 ↦ (True, {r2})
```
Whatever the embedding for `asp2pp`and whatever the direction, if you want an accurate embedding, you need both `m1` and `m2` to be accepted. However, at `s1`, `m` acts just like `m1` and at `s2`, `m` acts just like `m2`. Since the ordering for `PrePost` quantifies over all initial states, then there is no way to exclude `m` and `m` is included, even if the triple does not hold.

`PurePre * PurePost` attempt:
```ocaml
PurePre A  = { (a, P) : A * (A -> Prop) | P a }   (* a precondition with a witness *)
PurePost B = B -> Prop

(* Hoare *)
ordPrePost  (P1, Q1) (P2, Q2) = (P2 ⊆ P1) /\ (forall a, P2 a -> Q1 ⊆ Q2)
(* incorrectness *)
dualPrePost (P1, Q1) (P2, Q2) = (P1 ⊆ P2) /\ (forall b, Q2 b -> exists a, P2 a /\ Q1 b)
```

For Hoare logic, the twisted ordering makes the bare pair `(pre, post)` an exact embedding. For incorrectness logic, *no* ordering on `PrePost` can do that, as long as `bind` is monotone in the continuation. Suppose `(pre, post) <= prepost1(m)` held exactly when `post -> asp(pre)`. Take `m` returning 0 or 1, so `prepost1 m = (True, {0, 1})`, and
```ocaml
k  0 = (False, ∅)       k' 0 = (True, ∅)   = prepost1 diverge
k  1 = (True, {0})      k' 1 = (True, {0}) = prepost1 (ret 0)
```
- `k 0 <= k' 0` is forced, because the triple `[False] diverge [∅]` holds vacuously
- `k 1 <= k' 1` trivially
- So monotonicity gives `bind (prepost1 m) k <= bind (prepost1 m) k'`, i.e. `(False, {0}) <= (True, {0}) = prepost1 (ret 0)`
- But that would mean `[False] (ret 0) [{0}]` holds, which it doesn't

`PurePre` removes the incorrectness triples that hold vacuously by requiring `pre` to be inhabited. However, once you add state, you get the following type:
```ocaml
PurePreSt S = PurePre S = { (s0, P) : S * (S -> Prop) | P s0 } 
```
How do you choose a start state to witness the precondition? This would require one witness for the whole spec, but incorrectness logic really needs one witness per outcome.
